# รายงานและคู่มือ Workflow โปรเจกต์ (Project Workflow)

เอกสารนี้สรุป **ลำดับการทำงานที่แนะนำ** และ **เกณฑ์บังคับสำหรับ Agent/ผู้พัฒนา** เพื่อให้งานสอดคล้องกับโครงสร้างโปรเจกต์ APP RANGSAN และลดการแก้ไขผิด flow

**ดัชนีที่เกี่ยวข้อง:** [AGENTS.md](../AGENTS.md) · [PROGRESS_LOG.md](./PROGRESS_LOG.md) · [docs/README.md](./README.md) · [README.md](../README.md)

---

## 1. ขอบเขตประเภทงาน (scope)

ใช้ป้ายกำกับงานเพื่อสื่อสารผลกระทบและวิธีตรวจสอบ

| Scope | ความหมาย | ตัวอย่าง |
|--------|-----------|----------|
| **feat** | ฟีเจอร์ใหม่หรือขยายพฤติกรรมที่ผู้ใช้เห็น | หน้าใหม่, ปุ่ม/ฟลว์ใหม่ |
| **fix** | แก้บั๊กหรือพฤติกรรมผิดจากที่ออกแบบ | แก้ validation, แก้คำนวณ |
| **docs** | เฉพาะเอกสาร/markdown | README, คู่มือใน `docs/` |
| **chore** | เครื่องมือ, ฟอร์แมต, การตั้งค่า repo, งานที่ไม่เปลี่ยน UX โดยตรง | eslint config, สคริปต์ build |

งานที่เป็น **docs/chore** ต้องไม่เปลี่ยนพฤติกรรมระบบปลายทางของผู้ใช้โดยไม่ตั้งใจ — ถ้ามีการแตะโค้ดควรจำกัดขอบเขตและระบุในคำอธิบายงาน

---

## 2. ลำดับการทำงานที่แนะนำ

1. **เข้าใจงาน** — อ่านคำขอ, ประวัติแชท (ถ้ามี), และขอบเขต (scope)
2. **อ่านเอกสารที่เกี่ยวข้อง** — อย่างน้อย [DEVELOPER_GUIDE.md](./DEVELOPER_GUIDE.md); งานข้อมูล/ตาราง → [API_REFERENCE.md](./API_REFERENCE.md); ติดตั้ง/โคลน → [CLONE_APP.md](./CLONE_APP.md) หรือ [COPY_PROJECT_QUICK_GUIDE.md](./COPY_PROJECT_QUICK_GUIDE.md)
3. **สำรวจโค้ด** — ค้นหาจุดที่มีอยู่แล้วก่อนเขียนใหม่; จับคู่สไตล์และเลเยอร์ (เช่น `src/services/` สำหรับ Supabase)
4. **ลงมือแก้** — เปลี่ยนเฉพาะส่วนที่จำเป็น; ไม่ refactor ข้ามขอบเขต
5. **ตรวจสอบ** — ตาม [PROJECT_VERIFICATION.md](./PROJECT_VERIFICATION.md) เมื่อเป็นงานที่ส่งมอบหรือก่อน deploy; สำหรับเอกสาร → ตรวจลิงก์ภายในโปรเจกต์ (ดูหัวข้อ 4)
6. **บันทึก progress** — ถ้ามีการเปลี่ยนแปลงไฟล์: เพิ่มรายการใน [PROGRESS_LOG.md](./PROGRESS_LOG.md) และลบไฟล์ชั่วคราวที่ไม่เกี่ยวข้องออกจาก repo (รายละเอียดหัวข้อ 6)

---

## 3. กฎบังคับสำหรับ Agent (สรุป)

รายละเอียดเชิงกลไกอยู่ที่ **[.cursor/rules/project-workflow.mdc](../.cursor/rules/project-workflow.mdc)** และ **[AGENTS.md](../AGENTS.md)**

- ระบุ **scope** และ **ผลกระทบ** (user / dev / agent) ก่อนลงมือเมื่องานไม่ชัดเจน
- **progress log:** เมื่อจบรอบงานและมีการแก้ไขไฟล์ใน repo — บันทึกตามหัวข้อ 6 และ [PROGRESS_LOG.md](./PROGRESS_LOG.md)
- **docs/chore:** ไม่แตะพฤติกรรม production โดยไม่จำเป็น
- แก้หรือเพิ่ม markdown ที่มีลิงก์ `./` หรือ `../` ต้อง **ตรวจว่า path ชี้ไฟล์จริง**
- ไม่ commit ความลับ — ใช้ `.env.example` เป็นแม่แบบ; อ่าน [ENV_SETUP.md](../ENV_SETUP.md) เมื่อเกี่ยวกับ env

---

## 4. การตรวจลิงก์เอกสารภายในโปรเจกต์ (verification)

เมื่อแก้หรือเพิ่มเอกสาร:

- ตรวจทุกลิงก์แบบ relative ในไฟล์ที่แก้ (เช่น `./FILE.md`, `../AGENTS.md`)
- ตรวจว่าไฟล์เป้าหมายมีอยู่ใน repo (ชื่อตัวพิมพ์ใหญ่-เล็กตรงกับระบบไฟล์)
- อัปเดต **README.md** (ราก) และ **docs/README.md** เมื่อเพิ่มเอกสารหลักใหม่ เพื่อไม่ให้ดัชนีขาดหาย

---

## 5. ผลกระทบและ rollback (แม่แบบ)

| ด้าน | คำอธิบาย |
|------|----------|
| **ผู้ใช้ปลายทาง** | งาน docs/chore โดยทั่วไปไม่กระทบการใช้งานแอป |
| **dev / agent** | onboarding เร็วขึ้น ลด flow ผิดเมื่อมีดัชนีและกฎชัด |
| **rollback** | ลบหรือคืนค่าไฟล์เอกสาร/กฎที่เพิ่ม แล้วคืนดัชนีใน README ให้ตรงก่อนเปลี่ยน |

---

## 6. Progress log (บังคับเมื่อมีการเปลี่ยนแปลงไฟล์)

**ไฟล์:** [docs/PROGRESS_LOG.md](./PROGRESS_LOG.md) — บันทึกรวมที่เดียว ไม่แตกหลายไฟล์โดยไม่อัปเดต [docs/README.md](./README.md)

| กฎ | รายละเอียด |
|-----|-------------|
| **เมื่อไหร่** | ทุกครั้งที่ **จบรอบงาน** และได้แก้ เพิ่ม หรือลบไฟล์ใน repo (รวมเอกสารและกฎ `.cursor/`) |
| **ยกเว้น** | สำรวจอย่างเดียวโดยไม่เปลี่ยนไฟล์ใน workspace |
| **ลำดับ** | เพิ่มรายการใหม่ **ทันทีใต้** `<!-- progress-log-entries -->` ใน `PROGRESS_LOG.md` เพื่อให้รายการล่าสุดอยู่ด้านบนของหัวข้อรายการ |
| **รูปแบบ** | ใช้เทมเพลตใน `PROGRESS_LOG.md` — หัวข้อ `### YYYY-MM-DD — [scope] …` และ bullet สรุป / ไฟล์หลัก / ตรวจสอบ / ลบไฟล์ชั่วคราว |
| **ลบไฟล์ที่ไม่เกี่ยวข้อง** | ก่อนปิดงาน: ลบไฟล์ชั่วคราว สคริปต์ทดลอง หรือสำเนาที่สร้างระหว่างทำงานและไม่ได้ตั้งใจเก็บ — ไม่ให้ค้างใน repo |

กฎ Cursor และ AGENTS อ้างอิงส่วนนี้แบบเดียวกัน — ดู [.cursor/rules/project-workflow.mdc](../.cursor/rules/project-workflow.mdc) และ [AGENTS.md](../AGENTS.md)
